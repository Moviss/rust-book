# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A personal fork (`Moviss/rust-book`) of the Brown University (cognitive-engineering-lab) experimental edition of *The Rust Programming Language*, used for a Polish translation for personal learning — no contributions go upstream. On top of upstream `rust-lang/book`, the Brown edition adds interactive quizzes (`mdbook-quiz`), ownership/permission visualizations (`mdbook-aquascope`), and a JS feedback widget (highlights stored in `localStorage` only). Most changes are prose/quiz edits, not code.

Remotes: `origin` = the fork; `upstream` = Brown's repo, fetch-only (push URL disabled). Pull upstream changes with `git fetch upstream && git merge upstream/main`.

Deployment: `.github/workflows/pages.yml` builds the book on push to `main` and deploys to https://moviss.github.io/rust-book/ (`site-url = "/rust-book/"` in `book.toml`). Upstream's `main.yml` (tests + deploy to Brown's domain) was removed; tests and lints below are local-only.

## Build & test

Required external tools (match versions pinned in `.github/workflows/pages.yml`: mdBook, mdbook-quiz, aquascope + its nightly toolchain): `mdbook`, `mdbook-quiz`, `mdbook-aquascope`, `pnpm`. Rust toolchain is pinned by `rust-toolchain` (1.90).

```bash
cargo make build          # build JS extensions + book (output in book/)
cargo make watch          # mdbook serve --open + pnpm watch, in parallel; sets QUIZ_DEV_MODE / QUIZ_LIGHTWEIGHT_VALIDATE

# Without cargo-make:
(cd js-extensions && pnpm init-repo) && mdbook build

# Tests (as upstream CI ran them)
cargo test                                  # packages/tools (workspace default member)
(cd packages/mdbook-trpl && cargo test)     # note/listing preprocessors
(cd packages/trpl && cargo build) && mdbook test --library-path packages/trpl/target/debug/deps
mdbook test -c ch04-02-references-and-borrowing --library-path packages/trpl/target/debug/deps   # single chapter

# Lints (upstream CI; spellcheck is English-only and won't pass on translated text)
bash ci/spellcheck.sh list                  # aspell; add false positives to ci/dictionary.txt (keep sorted)
mdbook build && cargo run --bin lfp src     # flags local file paths in src
find ci tools -name '*.sh' -print0 | xargs -0 shellcheck

# JS extensions (js-extensions/)
pnpm lint && pnpm test
```

Formatting: `rustfmt` (max_width 80) for Rust, `dprint fmt <file>` for Markdown/TS/JSON.

## Architecture

**Content pipeline.** `src/SUMMARY.md` defines chapter order; `src/chXX-YY-*.md` are the chapters. `mdbook build` runs these preprocessors (configured in `book.toml`):
- `quiz` — expands `{{#quiz ../quizzes/<name>.toml}}`. `validate = true` means malformed quizzes fail the build.
- `aquascope` — renders ```` ```aquascope,<flags> ```` code blocks by actually compiling/analyzing the Rust snippet. Flags: `interpreter` (memory diagrams), `permissions` (R/W/O permission tables), plus modifiers `stepper`, `boundaries`, `shouldFail`, `horizontal`, `showFlows`, `concreteTypes`, `hideCode`. Lines prefixed `#` are hidden; `` `[]` `` marks a step where state is shown.
- `trpl-note` / `trpl-listing` — run via `cargo run --manifest-path packages/mdbook-trpl/Cargo.toml`, so no install is needed (README's `packages/mdbook-trpl-listing` / `-note` crates are separate copies kept for rust-lang/rust path deps).

**Quizzes** (`quizzes/*.toml`, named after the chapter/section they appear in). Each `[[questions]]` needs a unique UUID `id` — generate a fresh one for new questions; never reuse or change existing IDs (answers/telemetry are keyed by them). Types: `MultipleChoice` (`answer.answer` + `prompt.distractors`), `ShortAnswer`, `Tracing` (`prompt.program`, `answer.doesCompile`, `answer.lineNumber`, optional `answer.stdout`). Prompts may embed `aquascope` blocks. Extra allowed words for quiz spellcheck go in `words.dic`.

**Listings** (`listings/chNN-*/listing-NN-MM|no-listing-NN-*|output-only-NN-*/`) are full standalone Cargo projects (excluded from the workspace) pulled into the text with `{{#rustdoc_include path:anchor}}` / `{{#include ...}}` using `// ANCHOR: name` / `// ANCHOR_END: name`. Compiler output lives in `output.txt` and is regenerated by `tools/update-rustc.sh`; output that can't be scripted is inline and tagged `manual-regeneration`. A `rustfmt-ignore` file in a listing dir opts it out of formatting. Async chapter listings depend on the `packages/trpl` support crate. See `ADMIN_TASKS.md` for the full listing workflow, rustc version bumps, and listing releases.

**Other directories.**
- `packages/tools` — Rust bins for book maintenance (`lfp`, `release_listings`, nostarch conversion helpers).
- `js-extensions/packages/feedback` — React/TS highlight-and-comment widget, built to `dist/` and loaded via `book.toml` `additional-js/css` (`telemetry` and `consent-form` exist but are currently disabled there).
- `theme/`, `ferris.*` — custom CSS/JS for the HTML renderer.
- `book.toml` `[output.html.redirect]` keeps old chapter URLs working after renumbering — add entries when renaming/renumbering chapter files.

## Editing rules

- Edit only `src/`, `quizzes/`, `listings/`, and tooling. **Do not edit `nostarch/`** (print snapshots), nor the frozen `first-edition/`, `second-edition/`, `2018-edition/`, `redirects/`.
- Prose style (`style-guide.md`): title-case headings, hard-wrap at 80 chars, italics (not quotes) for introduced terms, method names without `()` in prose, relative links for intra-book and std docs.

## Polish translation

The book has been translated into Polish in place (`src/`, `quizzes/`, `SUMMARY.md`, `book.toml` title/`language = "pl"`, `ferris.js` tooltips); file names and URLs stay unchanged. Translation status: complete (all 120 files reviewed). New or changed upstream content must be translated following `tlumaczenie/PLAN.md` phase 6. Plan, progress, conventions and glossary live in `tlumaczenie/` (`PLAN.md`, `POSTEP.md`, `KONWENCJE.md`, `GLOSARIUSZ.md`); gate scripts and their self-tests are in `tlumaczenie/narzedzia/` (`python3 tlumaczenie/narzedzia/testy/uruchom.py`).

- **Code is untouched byte for byte** — code blocks, inline code, comments inside code, `aquascope` blocks, `@Perm{...}` markers, `listings/`, `output.txt`.
- **Heading anchors are pinned** to the original English ids with `{#id}` (e.g. `## Stos i sterta {#the-stack-and-the-heap}`). Keep them on every heading; add one to any new heading.
- **Quiz fields that stay unchanged:** `id`, `type`, `multipart` keys, `prompt.program`, `answer.doesCompile`, `answer.lineNumber`, `answer.stdout`, `prompt.answerIndex`, `prompt.sortAnswers`, ShortAnswer `answer.answer`/`answer.alternatives`, code-only MultipleChoice options, and code in any field.
- **Commits** are in English with no AI attribution trailers (no `Co-Authored-By`). One commit per chapter; stage explicit paths (`git add src quizzes tlumaczenie ...`), never `git add -A` (local `pnpm` dirties `js-extensions/pnpm-lock.yaml`).
- **Subagents** translating or reviewing must not use git except `git show`, and edit only their assigned files.
- `tlumaczenie/KONWENCJE.md` takes precedence over `style-guide.md` and the Title Case / hard-wrap rules above for translated text (Polish uses sentence-case headings).
- `tag pl-base` = upstream commit the translation is based on; `tag pl-source` = English source with pinned anchors, the reference all gates compare against (`sprawdz.py --ref pl-source`).
- **Do not sync `nostarch/book.toml`** with `book.toml`, despite the comment in `book.toml`.
- UI strings of the quiz widget and mdBook theme are compiled into their binaries; `tlumaczenie/narzedzia/spolszcz_widgety.py book` patches them in the build output (run in `pages.yml` after `mdbook build`). It fails if any expected string is missing, so after bumping `MDBOOK_VERSION` / `MDBOOK_QUIZ_VERSION` update its replacement table.
- Local builds skip aquascope: `MDBOOK_PREPROCESSOR__AQUASCOPE__OPTIONAL=true mdbook build -d tmp/book-pl`; CI does the full build.
